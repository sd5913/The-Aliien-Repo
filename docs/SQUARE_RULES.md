# Web v1.4 广场逻辑核对

依据：`PRD.md` 第 6.1、6.5、7.11 节及用户明确要求。广场公开表示可以发现与参与，不表示非发起者获得分享权限。

## 原实现的问题

1. 共用卡片无条件展示分享；复用组件时没有区分广场与个人列表。
2. 参与页无条件展示分享，因此只隐藏广场卡片按钮仍可从详情绕过。
3. 同一公开投票进入最近或个人参与记录后仍可分享；不能只依赖入口来源或 returnTo 控制。
4. 分享 Provider 无权限校验，隐藏按钮没有阻止误调用时立即复制链接和生成票根。
5. 广场卡片向发起者开放侧滑管理，且根据身份跳投票页或结果页，与“卡片只提供去投票”不一致。

## 本分支的规则

| 位置 / 身份 | 非发起者 | 发起者 |
| --- | --- | --- |
| 广场卡片 | 只有去投票，无分享、无侧滑管理 | 同样只有去投票；管理与分享在自己的路径操作 |
| 公开投票参与页 | 无分享入口 | 保留分享 |
| 公开投票结果页 | 无分享或自动弹分享 | 保留原有分享 |
| 最近、个人参与记录中的公开投票 | 无分享入口 | 自己的投票保留分享 |
| 分享 Provider | 非发起者拒绝调用，不复制或挂载票根浮层 | 允许；账号切换后重新判定展示权限 |

分享校验仅依据服务端返回的 `creatorId` 与当前正式账号，不依赖公开状态或导航来源。PRD 6.5 将分享列为仅所有者的管理操作；移除上一版 `isPublic === false` 也能分享的例外。参与过、登录其他正式账号、查看结束后的结果、投票从广场撤回，都不会给非发起者增加分享入口。所有权缺失时不授权。

广场仍遵循本分支已有过滤：公开、open、未到截止，按发布时间倒序，过滤后取 5 条；卡片显示参与人数。

## 验证范围

- 游客、其他正式账号、发起者的广场卡片均无分享和管理操作。
- 软登录用户进入参与页、刷新、提交、查看结果、`?share=1`、回最近均无公开投票分享入口。
- 发起者自己的最近卡片、参与页仍可打开分享浮层；非发起者在投票转为非公开后仍无分享入口。
- 此项仅为广场分享功能修复，不表示账号迁移、软删除或全部评论权限已完成；不创建 PR。

另发现 PRD 7.11 的“广场来源评论不显示头像”仍需独立核对：目前 CommentList 渲染头像，导航没有持久化广场来源。此次不将其误标为已完成。

首页目前将最近与广场纵向排列，尚未实现 PRD 6.1 的双 Tab；列表规则与页面结构需分别验收。

浏览器验证还发现个人中心将软身份参与记录再次按 owner 过滤而隐藏；这是参与记录功能的独立问题，不在本分支顺带修复，也不将“卡片未出现”当作分享权限验证通过。

验证涵盖六个单元测试文件，以及 Playwright 广场分享和原有账号参与/发布隐私两组。新增边界包括撤回广场、直接访问 `/share`、结束后结果页和剪贴板调用检查。外部 API 使用合成会话与拦截数据，没有修改线上数据。

本次重新核对后的结果：单元测试 6/6、浏览器测试 11/11、生产构建及 diff 检查全部通过。仍在 `fix/web-square-active-only` 分支，未创建 PR 或发布。
